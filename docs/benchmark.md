# Phase 0: объёмы данных и бенчмарк SQLite

Дата: 2026-07-24. Железо: Windows 11, локальный NVMe. Go 1.25, modernc.org/sqlite 1.54 (pure-Go, без CGO). Утилита: `cmd/benchdb`.

## Реальные объёмы (экспорт solidtime)

Полный экспорт аккаунта одного активного пользователя (6.4 года трекинга):

- 10 812 записей за 2342 календарных дня (1590 дней с трекингом)
- ~6.8 записей в день с трекингом, p95 = 15, максимум 27
- ~144 записи в месяц, максимум 303
- Описание: в среднем 30 символов, максимум 179
- 4 проекта, 15 тегов

Оценка: активный пользователь ~1700-2000 записей/год. 10 пользователей за 5 лет ~100k записей. Бенчмарк гонялся на 100k (реалистичный горизонт) и 1M (запас x10, эквивалент ~50 лет трекинга командой).

## Результаты

Схема из плана: TEXT UUID PK, unix-ms timestamps, индексы (user_id, server_seq), (user_id, started_at), partial на запущенные таймеры. WAL, synchronous=NORMAL. Один writer-коннект.

| Метрика | 100k записей | 1M записей |
|---|---|---|
| Bulk seed (batch 5000/tx) | 82k rows/s | 67k rows/s |
| Sync upsert (1 строка/tx + seq counter) | 0.18 ms/op (5420 ops/s) | 0.27 ms/op (3673 ops/s) |
| Отчёт за месяц (агрегация по проектам) | 0.19 ms | 0.26 ms |
| Отчёт за год | 1.93 ms | 2.84 ms |
| Отчёт за всё время | 12.8 ms | 203 ms |
| Sync pull (server_seq > ?, LIMIT 500) | 0.61 ms | 0.82 ms |
| Запущенные таймеры (partial index) | 0.01 ms | 0.02 ms |
| Размер файла БД | 38.8 MB | 388 MB |

## Выводы

- Реальная нагрузка (10 юзеров, ~1 запись в несколько минут суммарно) от лимитов SQLite отстоит на 3-4 порядка: писатель держит ~5000 одиночных sync-транзакций в секунду.
- Отчёты за месяц/год - доли миллисекунд/единицы миллисекунд на любом реалистичном объёме благодаря индексу (user_id, started_at). Индекс обязателен, оставлен в схеме.
- Единственная медленная операция - отчёт "за всю историю" на x10 объёме (203 ms при 100k записей у одного юзера). На реальном горизонте (10k записей/юзер) это 13 ms. Предагрегация не нужна; если когда-нибудь станет нужна - кэш агрегатов по закрытым месяцам.
- 407 bytes/запись (включая индексы) - TEXT-UUID тратят место, но 5 лет команды = ~40 MB файла. Оптимизация (BLOB UUID) не оправдана усложнением.
- Решение: схема утверждается без изменений, предагрегация в скоуп не входит.
