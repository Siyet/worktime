# Фронтенд: Svelte 5 vs Preact vs SolidJS

Контекст проекта: local-first PWA. Клиент пишет всё в IndexedDB, UI работает только с локальными данными, фоновая синхронизация с сервером когда есть сеть. Запущенный таймер - это entry с start и без stop, elapsed считается от timestamp - поэтому таймер работает оффлайн без всякой доп. механики. PWA закрывает мобильный сценарий без нативных приложений.

PWA/оффлайн-обвязка (vite-plugin-pwa, service worker, IndexedDB) работает одинаково со всеми тремя кандидатами - на выбор не влияет.

Итог: выбран **Svelte 5** (решение от 2026-07-24).

## Критерии

- Размер бандла - определяет первую загрузку на плохой связи (дальше shell идёт из кэша service worker).
- CPU/память на слабых телефонах.
- Качество кода, который генерит Claude - планируется плотная работа с claude design над UI.
- Экосистема и долговечность.

---

## Svelte 5 (выбран)

Компилятор: .svelte-компоненты компилируются в императивный DOM-код, VDOM нет вообще.

- Бандл реального приложения: ~30-45KB gzip.
- Реактивность через runes, минимум кода на компонент:

```svelte
<script lang="ts">
  let elapsed = $state(0);
  const label = $derived(formatDuration(elapsed));
</script>
<span>{label}</span>
```

- Двустороннее связывание форм, встроенные transitions - UI-код самый короткий из тройки.
- Экосистема средняя, но для трекера (роутер, обёртка над IndexedDB, date-утилиты) хватает с запасом.
- Claude пишет хорошо. Известная проблема - иногда смешивает синтаксис Svelte 4 и Svelte 5 (runes). Лечится правилом в CLAUDE.md проекта.

---

## Preact + @preact/signals

React-совместимый API в 4KB.

- Бандл: ~15-30KB gzip - самый маленький из тройки.
- Claude знает React-паттерны лучше всего остального - минимум ошибок генерации при итерациях UI через claude design.
- Signals: точечные обновления DOM мимо ре-рендера дерева. Таймер, тикающий каждую секунду, обновляет один текстовый узел, а не дерево компонентов.
- preact/compat открывает React-экосистему (следить за размером зависимостей).
- Минусы: VDOM (перф ниже Svelte/Solid, для трекера незаметно), редкие несовместимости compat с React-библиотеками.

---

## SolidJS

Fine-grained реактивность без VDOM, синтаксис JSX.

- Бандл: ~25-40KB gzip.
- Лучший рантайм-перф из тройки в бенчмарках.
- Системная проблема для LLM-генерации: JSX выглядит как React, но семантика другая. Деструктуризация props молча ломает реактивность. Компонент выполняется один раз - привычные React-паттерны (условный рендер через &&, списки через map) работают иначе (нужны Show, For). Claude периодически генерит "React-стиль", который компилируется и даже частично работает, но тихо теряет реактивность - такие баги ищутся долго.
- Экосистема меньше Svelte.

---

## Отброшенные варианты

- **React**: 45KB+ рантайма до первой строчки своего кода. Всё, что даёт React, Preact даёт в 4KB.
- **Vue 3**: бандл 60-80KB, преимуществ для этой задачи нет.
- **Qwik**: resumability решает проблему гидрации SSR-страниц - у нас local-first SPA за логином, этой проблемы нет. Экзотика мешала бы и разработке, и LLM-генерации.
- **HTMX / серверный рендеринг**: оффлайн-таймер требует полноценного клиентского state и service worker - модель "HTML с сервера" противоречит local-first.
- **SSR в целом**: приложение живёт за логином (индексировать нечего), после первого визита shell грузится из кэша service worker мгновенно даже без сети. "Быстрая загрузка на плохой связи" решается маленьким бандлом + кэшем, а не SSR.

## Сводная таблица

| Критерий | Svelte 5 | Preact + signals | SolidJS |
|---|---|---|---|
| Бандл (gzip) | 30-45KB | 15-30KB | 25-40KB |
| Перф на слабом железе | отлично | хорошо | отлично |
| Claude-генерация UI | хорошо | отлично | средне (тихие ловушки) |
| Экосистема | средняя | React через compat | маленькая |
| Код компонентов | самый лаконичный | React-стиль | React-подобный с нюансами |

## Вердикт

- **Svelte 5** - лучший баланс: маленький бандл, топ-перф, самый лаконичный код. Выбран.
- **Preact** - близкий второй: React-паттерны Claude пишет безошибочнее всего, бандл даже меньше.
- **SolidJS** - только если рантайм-перф важнее удобства LLM-итераций.
